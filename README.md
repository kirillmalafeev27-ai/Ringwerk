# RINGWERK

Бодрая 2D-аркада для практики немецкого языка от A1 до B2. Перед сменой игрок выбирает одну из 49 лексических и 52 грамматических тем, а затем отвечает в режиме узнавания, свободного воспроизведения или аудирования. Три кольца непрерывно вращаются, неподвижные угрозы пересекают траекторию игрока, а правильный ответ сохраняет остаток быстро сгорающего импульса.

## Цель

Активируйте узлы A, B и C в любом порядке, учитывая пользу и цену каждого протокола, затем доберитесь с внутреннего кольца до центрального выхода.

## Управление

- `1–4` — выбрать ответ в режиме узнавания или аудирования.
- `Enter` — отправить свободный немецкий ответ в режиме воспроизведения.
- `A / D` — шаг по кольцу.
- `W / S` — перейти на внешнее или внутреннее кольцо.
- `Space` — зацепиться за ближайшую спицу или отпустить её.
- `Q` — прыжок между крайними кольцами при импульсе от 80%.
- `Z / X` — применить бонус из одного из двух слотов.
- `P` — включить или выключить звук.

## Локальный запуск

Нужен Node.js 24.19.x.

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

## Форматы заданий

Формы упражнений и правила их составления лежат в [`lib/exercise-formats.ts`](lib/exercise-formats.ts) — том же наборе, что использует генератор See Escape:

- `gap` — немецкая фраза с ровно одним пропуском `___`; четыре варианта отличаются только проверяемым признаком.
- `word-order` — части предложения через ` / `; четыре варианта собраны из тех же частей и отличаются только порядком слов. Ответ, который тратит не все части или добавляет свои слова, отбраковывается на сервере.
- `word-field` — Wortfelder: немецкая фраза с одним пропуском на месте стёртого повседневного слова (`sagen`, `gehen`, `gut` ...); четыре варианта — синонимы этого же слова, и по контексту подходит ровно один. Поле слова всегда держит пять синонимов, панель показывает все пять, а на кнопки попадают четыре, так что за пакет отрабатываются все.
- `audio` — немецкая фраза только звучит; четыре варианта — русские переводы. Текст фразы не печатается ни в задании, ни в переводе; после ответа он показывается в строке разбора.

### Wortfelder: синонимы вместо затёртых слов

Пятнадцать полей в `WORD_FIELDS` — девять глагольных (`sagen`, `gehen`, `essen`, `sehen`, `machen`, `geben`, `helfen`, `denken`, `bekommen`) и шесть от прилагательных (`gut`, `groß`, `schnell`, `schön`, `schlecht`, `wichtig`) — по пять синонимов в каждом, у каждого синонима записан контекст, который выбирает именно его: `flüstern` — «говорить очень тихо, почти на ухо», `rufen` — «громко звать издалека».

Задание выглядит так: «Das Baby schläft, deshalb ___ wir nur noch.» при вариантах `flüstern / rufen / murmeln / behaupten`. Выбор решает не грамматика, а сигнал в предложении.

Две вещи, которые держат формат честным:

- **перевод остаётся нейтральным.** «Малыш спит, поэтому мы теперь только **говорим**» — если написать «шепчем», задание решается переводом, а не немецким контекстом. Это главный подвох формата, и требование вынесено в правила запроса отдельной строкой;
- **четыре варианта обязаны быть синонимами одного поля.** Модель присылает `wordField` и `optionBases` — словарные формы всех четырёх вариантов, — и сервер сверяет их с каталогом. Не сошлось — задание не доходит до игрока. Внутри пакета один синоним может быть правильным ответом только раз, поэтому пакет расходится по всем пяти, а не по двум самым очевидным.

Уровень задаёт не синонимы, а сложность предложения вокруг пропуска: на A1 доступны четыре самых конкретных поля, на B2 — все пятнадцать. Каталог прокручивается: соседние пакеты берут следующие поля, а не одни и те же.

Формат выбирается темой `Wortfelder & Synonyme` в списке грамматики (группа «Лексика»).

`TOPIC_RULES` там же — построчный свод правил по каждой грамматической теме. Он уходит в запрос вместе с общими требованиями к качеству и закрывает главную беду генерации: задания, решаемые по второму, непроверяемому признаку.

Аудирование озвучивается через ElevenLabs, если задан `ELEVENLABS_API_KEY`, и через голос браузера, если нет, — режим играется в обоих случаях. `/api/tts` отдаёт mp3 по немецкой фразе и держит её в памяти, чтобы повтор не оплачивался дважды.

## Вопросный поток

Клиент держит отдельную очередь для комбинации `уровень | лексика | грамматика`, получает синтетические пакеты по 8 вопросов и начинает фоновое пополнение при остатке меньше 3. Узнавание и воспроизведение намеренно делят один пул; аудирование не привязано к грамматической теме и держит очередь `уровень | лексика`. Последние 60 формулировок передаются в `exclude`; история дедупликации хранит 80 вопросов. Если сервер, сеть или модель недоступны, игра без ожидания использует встроенный разноуровневый резерв. Неправильно решённый вопрос возвращается в хвост очереди.

AITunnel вызывается только на сервере: для генерации пакетов и для смысловой проверки свободного ответа, если строгое локальное сравнение не сработало. Во время сетевой проверки импульс, арена и общий таймер фиксируются, поэтому задержка провайдера не влияет на результат забега. Для локального production-режима скопируйте `.env.example` в `.env.local` и задайте `AITUNNEL_API_KEY`. `/api/questions/status` показывает только готовность серверной конфигурации, не раскрывая ключ, провайдера или модель.

## Northflank

Репозиторий готов к Combined Service из корневого `Dockerfile`:

- build type: `Dockerfile`, context `/`;
- public HTTP port: любой номер в port entry — Northflank **не** подставляет `$PORT`, поэтому без `PORT`/`PORTS` контейнер слушает сразу `8080` и `3000`, и любой из этих номеров в entry доходит до приложения. Для другого номера задайте `PORT` (или `PORTS` через запятую) в переменных сервиса;
- readiness/liveness: `GET /healthz` на том же порту;
- runtime secret: `AITUNNEL_API_KEY`; необязательный — `ELEVENLABS_API_KEY` для озвучки аудирования;
- необязательные runtime variables перечислены в `.env.example`;
- одна реплика для in-memory кэша пакетов (при масштабировании нужен общий Redis-lock/cache).
- run command можно не задавать (`node northflank-serve.mjs` из `CMD`); `npm start` и `npm run start:northflank` внутри образа ведут туда же.

Контейнер собирает отдельный vinext standalone runtime с `DEPLOY_TARGET=node`, слушает на `0.0.0.0` и не содержит `.env`-файлы. Обычная сборка без `DEPLOY_TARGET=node` остаётся Cloudflare/Sites-сборкой.

Если сервис собирается из репозитория, а не из `Dockerfile` (buildpack/Git-сборка), то:

- build command: `npm ci --no-audit --no-fund && npm run build:node`;
- run command: `npm run start:northflank` — или оставьте пустым: `npm start` теперь ведёт в тот же скрипт.

`npm run start:northflank` подставляет `NODE_ENV=production` и `HOST=0.0.0.0`, разбирает `PORT`/`PORTS`, пишет в лог итоговый список портов и сам собирает standalone-выход, если сборка прошла без `DEPLOY_TARGET=node`. `npm run start:vinext` — это прежний `vinext start` на одном порту.

### Ingress отвечает `Connection refused`

`upstream connect error ... Connection refused` приходит от прокси Northflank, а не от приложения: контейнер поднялся, но на порту, куда постучался прокси, никто не слушает. По порядку:

1. Сервис собирается из ветки, где есть корневой `Dockerfile` и `scripts/start-northflank.mjs`? Без них buildpack запустит `npm start` из старого `package.json`, а он до ingress не доходит.
2. Номер в port entry совпадает с тем, что в логе старта: `[northflank] PORT=... PORTS=... -> binding ... on 0.0.0.0`.
3. Если номер нестандартный — задайте `PORT` или `PORTS` в переменных сервиса и передеплойте.
